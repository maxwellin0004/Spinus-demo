# Tanglin V1 产品设计文档

## 1. 产品定位

Tanglin V1 是一个面向小商家的自助式 KOL 宣发任务平台。

核心业务闭环：

```text
商家创建 Campaign
-> 商家托管 Campaign 预算
-> KOL 自由申请任务
-> 商家审核 KOL 申请
-> KOL 创作并发布内容
-> 商家验收发布链接
-> KOL 获得结算
```

V1 不是大品牌投放系统，不是完整达人市场，也不是重运营代理服务系统。V1 优先解决：小商家快速自助发任务、KOL 清楚接单履约、平台通过资金托管和规则约束建立信任，并在争议、账号审核、财务处理上做轻量介入。

## 2. 目标用户

### 商家

适合希望快速找 KOL 做种草、App 下载、店铺/活动引流、测评体验的小商家。

商家需要：

- 引导式 Campaign 创建流程。
- 清晰的预算和托管规则。
- 手动筛选 KOL 申请。
- 可选择是否审稿。
- 简单的发布链接验收。
- Campaign 履约报表。
- 可退回的商家余额。

### KOL

KOL 可以浏览开放任务，使用已验证社媒账号申请，提交内容草稿或预览附件，发布内容，提交发布链接，并申请提现。

KOL 需要：

- 移动端优先的任务发现和履约体验。
- 清晰的任务要求和截止时间。
- 社媒账号验证状态。
- 可预期的结算规则。
- 钱包和提现流程。

### Admin

平台运营人员负责付款确认、社媒账号验证、争议处理、退款、提现、规则配置和审计。

V1 中 Admin 权限基本一致，但只有 Owner 可以创建新的 Admin 账号。

## 3. 角色能力

### 商家能力

- 注册并完成轻量认证。
- 在认证完成前创建 Campaign 草稿。
- 完成轻量认证和资金托管后正式发布 Campaign。
- 使用 6 步 Campaign Wizard。
- 上传 Campaign 级轻量素材或填写外部素材链接。
- 默认手动审核 KOL 申请。
- 批量拒绝申请，勾选后批量通过申请。
- 选择是否需要审稿。
- 如需审稿，最多要求 2 轮修改。
- 验收或拒绝 KOL 发布链接。
- 查看 Campaign 履约报表。
- 导出 Campaign 报表 CSV。
- 使用商家余额发布新任务。
- 申请人工退回可用余额。

### KOL 能力

- 自然注册。
- 完善个人资料。
- 添加社媒账号。
- 手动填写粉丝数和平均播放。
- 查看社媒账号是否已验证。
- 浏览开放任务。
- 申请任务时填写轻量申请说明并选择发布账号。
- 提交结构化草稿。
- 可选上传成品预览附件。
- 根据商家意见修改草稿，最多 2 轮。
- 发布后提交发布链接。
- 被拒绝验收后，在最终截止时间前可多次补交。
- 查看钱包余额。
- 申请人工提现，最低提现金额为 ￥20。

### Admin 能力

- 确认商家付款凭证。
- 验证 KOL 社媒账号。
- 处理任务争议和高金额验收超时复核。
- 手动裁定全额结算、退款、继续补交或部分结算。
- 处理 KOL 提现申请。
- 处理商家余额退款申请。
- 查看最小财务总账。
- 导出财务流水 CSV。
- 维护固定字段规则配置。
- 查看审计日志。
- Owner 可创建 Admin 账号。

## 4. Campaign Wizard

V1 使用完整 Campaign Wizard，但体验上应像引导式问卷，高级配置可以展开。

Wizard 共 6 步。

### 第 1 步：推广目标

字段：

- 品牌或产品名称。
- 产品或活动链接。
- 推广目标。
- 行业/分类。
- 产品介绍。

### 第 2 步：目标 KOL

字段：

- 目标平台。
- 目标国家/地区。
- 目标语言。
- 内容形式。
- 最低粉丝数。

### 第 3 步：平台任务

商家需要按平台分别配置任务。

每个平台字段：

- 平台。
- 内容形式。
- KOL 招募人数。
- 每个 KOL 固定奖励。
- 交稿截止时间。
- 发布截止时间。
- 平台补充要求。

系统根据这些平台配置自动创建 `CampaignTask`，正常 V1 流程中不再要求 Admin 手动拆任务。

### 第 4 步：内容要求

字段：

- 必须包含内容。
- 禁止表达。
- 广告披露要求。
- 是否需要审稿。
- 修改轮次，V1 固定最多 2 轮。
- 验收规则。

所有付费任务都必须要求广告披露，商家不能关闭。

### 第 5 步：素材与验收

字段：

- Campaign 级素材上传。
- 外部素材链接。
- 发布证明规则。
- 验收 SLA。
- 补交截止规则。

V1 的发布证明只要求发布链接，不强制截图和数据指标。

### 第 6 步：预算与发布

字段和行为：

- 托管总额 = 各平台任务人数 × 每人奖励之和。
- 平台服务费字段保留，但 V1 为 0。
- 币种为 CNY。
- 商家余额足够时，冻结余额并发布。
- 商家余额不足时，为差额生成付款单。
- 商家上传付款凭证。
- Admin 确认付款后 Campaign 进入可发布状态。

## 5. V1 模板

V1 只提供少量系统模板，不做模板市场。

模板：

- 新品种草。
- App / 小程序下载。
- 店铺 / 活动引流。
- 测评 / 体验分享。

模板只预填推荐推广目标、平台、内容要求示例、禁止表达示例和验收规则。商家仍需确认预算、人数、奖励和素材。

## 6. 支持平台与分类

V1 只做中文和人民币。

支持平台：

- 小红书。
- 抖音。
- 微信视频号。
- B站。
- 微博。

内容/行业分类使用固定枚举，不做自由标签系统。

建议分类：

- 美妆护肤。
- 食品饮料。
- 服饰配饰。
- 数码家电。
- App / 小程序。
- AI / 工具软件。
- 本地生活。
- 教育课程。
- 母婴亲子。
- 健身运动。
- 家居好物。
- 其他。

## 7. KOL 申请流程

V1 重点做 KOL 自由申请，不做 KOL 搜索、邀请或推荐。

默认规则：

- 商家默认手动审核 KOL 申请。
- 默认只有至少一个已验证社媒账号的 KOL 可以申请。
- 商家可以明确允许未验证账号申请。
- 同一 Campaign 下，一个 KOL 默认只能接 1 个任务。

KOL 申请表单：

- 选择社媒账号。
- 填写轻量申请说明。

商家审核申请：

- 逐个通过。
- 逐个拒绝。
- 批量拒绝。
- 勾选后批量通过，并显示名额和奖励确认。

## 8. 审稿流程

商家发布任务时选择是否需要审稿。

如果需要审稿：

```text
KOL 提交草稿
-> 商家通过、拒绝或要求修改
-> KOL 修改
-> 最多 2 轮修改
-> 草稿通过后 KOL 发布
```

草稿字段：

- 标题或 Hook。
- 脚本或内容大纲。
- Caption / 文案。
- Hashtags。
- 封面文字。
- 广告披露位置说明。
- 可选预览附件。

预览附件限制：

- 图片：jpg、png、webp。
- 视频：mp4、mov。
- 单文件最大 50 MB。
- 不转码。
- 仅用于商家审稿预览。

商家要求修改时必须填写：

- 结构化原因。
- 文字说明。

草稿通过后，KOL 不应大幅修改内容。重大修改必须重新提交审核。

## 9. 发布证明与验收

V1 发布证明只要求发布链接。

规则：

- 链接必须通过平台/域名/格式基础校验。
- 不允许重复提交同一个链接。
- 链接在验收前不可访问、删除、私密或地区不可访问时，默认 KOL 负责。
- KOL 可在最终截止时间前补交链接。

商家验收：

- 通过：进入结算。
- 拒绝：必须选择结构化原因并填写文字说明。

结构化拒绝原因：

- 链接无法访问。
- 发布平台或账号不符合要求。
- 发布内容与已通过草稿不一致。
- 未包含必须内容。
- 出现禁止表达。
- 未按要求披露广告。
- 发布时间超时。
- 内容已删除或设为私密。
- 其他。

## 10. SLA 与截止时间

核心截止时间：

- 交稿截止时间。
- 发布截止时间。

商家验收 SLA：

- 默认 3 天。
- 超时前提醒。
- 低金额任务超时自动通过。
- 高金额任务超时进入 Admin 复核。

默认配置：

- 高金额阈值：￥50。
- KOL 补交宽限期：2 天。

KOL 超时：

- 先提醒。
- 超过宽限期后自动取消或进入商家处理。

## 11. 托管、余额与结算

币种：

- 仅人民币。

奖励规则：

- V1 只支持固定基础奖励。
- 不做播放、点击、转化奖金。

商家托管：

- 按 Campaign 总额一次性托管。
- 托管总额为所有平台任务奖励之和。
- 平台服务费字段保留，但 V1 为 0。

商家余额：

- 可用余额可冻结用于发布新 Campaign。
- 余额不足时，商家补差额付款。
- Campaign 未使用完的托管余额在关闭后退回商家可用余额。
- 商家可申请人工退回可用余额。

KOL 钱包：

- 可用余额。
- 冻结余额。
- 累计收入。
- 提现记录。

提现：

- 最低提现 ￥20。
- Admin 人工处理。
- 提现金额申请后冻结。
- 拒绝则退回可用余额。
- 支付完成后计入累计提现。

## 12. 退款规则

V1 使用简单分段退款规则：

- 未开始：可退。
- 已交稿：KOL 获得 50%。
- 已发布且符合要求：KOL 获得 100%。

平台服务费 V1 为 0，但数据模型和财务视图保留相关字段。

## 13. 争议处理

V1 提供最小 Admin 争议处理页面。

争议证据主要以平台内结构化记录和提交凭证为准，不接受站外聊天作为主要证据。

Admin 争议页面展示：

- Campaign brief。
- KOL 申请信息。
- 草稿记录。
- 商家修改或拒绝原因。
- 发布链接历史。
- 商家验收拒绝原因。
- KOL 补交记录。
- 时间线。
- 资金状态。

Admin 可裁定：

- 通过并结算。
- 驳回并退款。
- 允许继续补交。
- 部分结算。

部分结算：

- 仅 Admin 可操作。
- 手动输入金额。
- 必填裁定原因。
- 必须写入审计日志。

## 14. 风控与合规

V1 不做强制高风险行业审核，但需要软提示和可配置风险分类。

广告披露：

- 所有付费任务强制广告披露。
- 商家不能关闭。
- V1 不做自动检测。
- 在关键流程节点显性确认广告披露要求。

站外交易：

- V1 只做规则和提示。
- 不做复杂联系方式自动检测。
- Admin 可人工记录违规。

商家和 KOL 风险状态：

- 正常。
- 限制功能。
- 冻结账号。

违规记录：

- 虚假链接。
- 超时未交付。
- 内容违规。
- 恶意拒绝验收。
- 诱导站外交易。
- 侵权素材。
- 争议败诉。
- 其他。

## 15. 通知与首页

V1 只做站内通知。

不做邮件、短信、微信、WhatsApp 或即时通讯。

各角色首页应采用待办优先的仪表盘。

商家待办：

- 待付款。
- 待审核 KOL 申请。
- 待审稿。
- 待验收发布链接。
- 即将超时。

KOL 待办：

- 待完善资料。
- 待社媒账号验证。
- 待交稿。
- 待修改。
- 待发布。
- 待补交。
- 提现状态。

Admin 待办：

- 待确认付款。
- 待审核社媒账号。
- 待处理争议。
- 高金额超时复核。
- 待处理提现。
- 待处理商家退款。

## 16. 报表与导出

V1 导出：

- Campaign 报表 CSV。
- 财务流水 CSV。

Campaign 报表重点是履约状态，不强调效果归因。

Campaign 报表字段：

- KOL 名称。
- 社媒账号。
- 平台。
- 申请状态。
- 草稿状态。
- 发布链接。
- 发布时间。
- 验收状态。
- 结算金额。
- 拒绝或争议原因。

财务流水字段：

- 商家付款。
- 商家余额变动。
- Campaign 托管冻结/释放。
- KOL 钱包入账。
- KOL 提现。
- 商家退款。
- 关联对象。
- 操作人。
- 时间。

## 17. 状态机

V1 必须严格定义和执行状态流转。

业务状态按阶段拆分：

### CampaignStatus

控制 Campaign 是草稿、待付款、进行中、暂停、完成、取消或归档。

### ApplicationStatus

控制 KOL 申请是已申请、已通过、已拒绝或已取消。

### DraftReviewStatus

控制是否需要审稿、草稿是否提交、是否要求修改、是否通过或拒绝。

### PublicationStatus

控制是否待发布、已提交链接、已验收、已拒绝、已补交、争议中或已过期。

### SettlementStatus

控制奖励是否已托管、待支付、已入钱包、已退款、部分结算或取消。

避免继续用单个宽泛的 `SubmissionStatus` 表示所有业务阶段。

## 18. Admin 设置

V1 使用固定字段设置页，不给运营暴露 key-value 配置表。

设置项：

- 商家验收 SLA，默认 3 天。
- 高金额 Admin 复核阈值，默认 ￥50。
- KOL 补交宽限期，默认 2 天。
- 最低提现金额，默认 ￥20。
- KOL 预览附件大小，默认 50 MB。
- 平台服务费比例，默认 0%。
- 平台联系邮箱。

风险行业分类可作为单独配置区域。

## 19. V1 不做什么

V1 不做：

- KOL 搜索和邀请。
- 自动匹配或推荐。
- 复杂创作者评分。
- 多币种。
- 多语言。
- 正式发票流程。
- 站内聊天。
- 完整客服工单系统。
- 社媒平台 API 数据抓取。
- 自动播放量、点赞、点击、转化追踪。
- 视频转码。
- 大型 Campaign 视频素材库。
- 模板市场。
- 复杂 Admin 权限矩阵。
- 自动联系方式检测。
- 强制高风险行业审批流程。

一般咨询使用平台联系邮箱。业务争议、商家退款和 KOL 提现必须留在系统内结构化处理。

## 20. 从当前代码迁移方向

当前代码不需要推倒重写。保留现有 Next.js App Router、Prisma、三角色结构、通知、审计日志、Campaign/Task/Application/Draft/Proof/Wallet 概念和 CSV/API 基础。

有边界重构优先级：

1. 将当前 Campaign Wizard 替换为 V1 六步自助 Wizard。
2. 根据商家平台配置自动生成 CampaignTask。
3. 增加 CNY 托管、商家余额、冻结金额和退款申请逻辑。
4. 将流程状态拆成 Campaign、Application、DraftReview、Publication、Settlement。
5. 将任务大厅平台和分类改为中文 V1 选项。
6. 将 Proof 简化为发布链接提交。
7. 增加商家验收 SLA、补交截止和高金额 Admin 复核。
8. 增加最小争议处理页面，支持部分结算。
9. 增加社媒账号审核队列。
10. 增加最小财务总账和 CSV 导出。
11. 增加固定字段 Admin 设置页。
12. 确保资金、争议、审核、冻结、退款、提现等关键操作写入审计日志。
