# Tanglin V1 实施计划

本文档将 `docs/TANGLIN_V1_PRODUCT_DESIGN.md` 中的产品设计转化为当前 Next.js + Prisma 代码库的工程实施计划。

## 1. 指导原则

- 保留当前应用结构。
- 不推倒重写。
- 复用现有 Admin、Brand、Creator 三端壳层。
- 复用现有鉴权、通知、审计日志、Prisma client 等基础工具。
- 优先保证状态流转和资金流转正确。
- UI 细节在主流程稳定后再优化。
- V1 只做中文和人民币。

## 2. Phase 1：数据模型改造

修改文件：

```text
prisma/schema.prisma
```

### 2.1 Campaign 与 Task

需要增加或调整：

- Campaign 待付款状态。
- 默认币种 CNY。
- Campaign 托管总额。
- 平台服务费金额，V1 默认为 0。
- 商家冻结托管金额。
- 是否需要审稿。
- 修改轮次，默认 2。
- 商家验收 SLA 快照。
- 高金额复核阈值快照。

平台任务配置字段：

- 平台。
- 内容形式。
- KOL 名额。
- 每个 KOL 固定奖励。
- 最低粉丝数。
- 交稿截止时间。
- 发布截止时间。
- 平台补充要求。

### 2.2 流程状态拆分

新增更清晰的阶段状态：

- `DraftReviewStatus`
- `PublicationStatus`
- `SettlementStatus`

不要继续扩展一个宽泛的 `SubmissionStatus` 来承载所有业务含义。

### 2.3 商家余额

当前 `BrandProfile.budgetBalance` 可以先保留，但需要增加明确的商家账务能力：

- 商家可用余额。
- Campaign 托管冻结/释放记录。
- 商家退款申请。

建议新增模型：

- `BrandLedgerTransaction`
- `BrandRefundRequest`

### 2.4 社媒账号验证

复用 `SocialAccount.verificationStatus`，但补充 Admin 审核队列需要的字段：

- 手填粉丝数。
- 手填平均播放。
- 审核说明。
- 验证时间。

### 2.5 争议

扩展现有 `Dispute`：

- 关联 Campaign、Application 或 Publication。
- 商家拒绝原因。
- KOL 补充说明，后续可扩展。
- Admin 裁定。
- 部分结算金额。
- 裁定说明。
- 状态。

### 2.6 平台设置

新增固定字段平台设置模型：

- 商家验收 SLA 天数。
- 高金额复核阈值。
- KOL 补交宽限天数。
- 最低提现金额。
- KOL 预览附件大小上限。
- 平台服务费比例。
- 平台联系邮箱。

## 3. Phase 2：资金核心

在 Campaign 正式改造前，先实现资金底层能力。

### 3.1 商家余额

新增 actions：

- 为 Campaign 差额创建付款单。
- 商家提交付款凭证。
- Admin 确认付款。
- 冻结商家余额用于 Campaign。
- 将未使用托管金额释放回商家余额。
- 商家创建退款申请。
- Admin 处理商家退款。

### 3.2 KOL 钱包

保留现有钱包和提现流程，但 V1 默认：

- 币种 CNY。
- 最低提现 ￥20。
- 只做人工处理，不接自动打款。

### 3.3 财务流水

新增 Admin 财务总账页面：

- 商家付款。
- 商家余额变动。
- Campaign 托管冻结/释放。
- KOL 入账。
- KOL 提现。
- 商家退款。

新增财务流水 CSV 导出。

## 4. Phase 3：Campaign Wizard

将当前 Wizard 改成 V1 六步：

1. 推广目标。
2. 目标 KOL。
3. 平台任务。
4. 内容要求。
5. 素材与验收。
6. 预算与发布。

实施要点：

- 使用中文平台枚举：小红书、抖音、视频号、B站、微博。
- 使用固定中文分类。
- 每个平台/内容形式配置自动生成一条 `CampaignTask`。
- 高级配置放在每个步骤里展开，不单独做很多步骤。
- Campaign 没有可用托管资金时不能 ACTIVE。

## 5. Phase 4：KOL 任务大厅与申请

修改 Creator 任务大厅：

- 按中文平台筛选。
- 按地区、语言、内容形式、最低奖励筛选。
- 展示执行所需 brief。
- 隐藏商家总预算和内部财务字段。

申请行为：

- KOL 选择一个社媒账号。
- KOL 填写轻量申请说明。
- 默认只有已验证社媒账号可申请。
- 默认限制同一 Campaign 下一个 KOL 只能接 1 个任务。

商家审核：

- 逐个通过/拒绝。
- 批量拒绝。
- 勾选后批量通过，并确认名额和托管奖励。

## 6. Phase 5：审稿流程

实现审稿逻辑：

- Campaign/Task 可选择是否需要审稿。
- 不需要审稿时，KOL 通过申请后直接进入发布阶段。
- 需要审稿时，KOL 提交结构化草稿。
- 支持可选预览附件，最大 50 MB，不转码。
- 商家可通过或要求修改。
- 修改轮次最多 2 轮。
- 修改要求必须包含结构化原因和文字说明。

## 7. Phase 6：发布链接与验收

简化 Proof：

- 必填发布链接。
- 校验平台/域名/格式。
- 禁止重复链接。
- 链接不可访问或失效，默认 KOL 负责。

商家验收：

- 通过。
- 拒绝，必须填写结构化原因和说明。
- KOL 在最终截止时间前可补交。

SLA：

- 商家验收 SLA 默认 3 天。
- 低金额超时自动通过。
- 高金额超时进入 Admin 复核。

## 8. Phase 7：争议与 Admin 复核

新增最小 Admin 争议/复核页面：

- Campaign 信息。
- KOL 申请信息。
- 草稿记录。
- 发布链接历史。
- 拒绝原因。
- 时间线。
- 资金状态。

Admin 可裁定：

- 全额结算。
- 全额退款。
- 允许继续补交。
- 部分结算，手动输入金额和说明。

所有裁定必须写入审计日志。

## 9. Phase 8：社媒账号审核队列

新增 Admin 待验证社媒账号队列：

- KOL。
- 平台。
- 账号链接。
- 手填粉丝数。
- 手填平均播放。
- 国家/地区。
- 内容分类。
- 提交时间。

Admin 操作：

- 通过。
- 拒绝。
- 填写说明。

## 10. Phase 9：设置、规则与风控

新增固定字段 Admin 设置页：

- 商家验收 SLA 天数。
- 高金额复核阈值。
- KOL 补交宽限期。
- 最低提现金额。
- KOL 预览附件大小。
- 平台服务费比例。
- 平台联系邮箱。

新增轻量规则中心或静态规则页面：

- 商家发布任务规则。
- KOL 接单和交付规则。
- 广告披露规则。
- 验收和补交规则。
- 退款和结算规则。
- 违规与冻结规则。

## 11. Phase 10：报表与 CSV

Campaign 报表重点展示履约：

- KOL 名称。
- 社媒账号。
- 平台。
- 申请状态。
- 草稿状态。
- 发布链接。
- 验收状态。
- 结算金额。
- 拒绝/争议原因。

财务报表：

- 按时间范围展示流水。
- 支持 CSV 导出。

## 12. 建议开发顺序

1. 增加平台设置默认值和常量。
2. 重构 Prisma schema，补充状态和资金模型。
3. 实现财务流水和商家余额底层能力。
4. 重做 Campaign Wizard 并自动生成 Task。
5. 更新 KOL 任务大厅和申请限制。
6. 实现审稿和附件限制。
7. 实现发布链接 Proof 和商家验收。
8. 实现 SLA，可先在页面读取或 Admin 队列查询时计算。
9. 实现争议和部分结算。
10. 实现社媒账号审核队列。
11. 实现报表和 CSV。
12. 跑迁移、更新 seed、lint/build 验证。

## 13. 验证清单

主流程：

```text
商家注册/登录
-> 商家创建 Campaign
-> 商家上传付款凭证
-> Admin 确认付款
-> Campaign 变为 ACTIVE
-> KOL 通过已验证社媒账号申请
-> 商家通过申请
-> KOL 提交草稿
-> 商家通过草稿
-> KOL 提交发布链接
-> 商家验收
-> KOL 钱包入账
-> KOL 申请提现
-> Admin 标记提现已支付
```

边界流程：

- 商家拒绝草稿两次。
- KOL 交稿超时。
- 商家拒绝发布链接。
- KOL 补交链接。
- 商家验收超时。
- 高金额任务进入 Admin 复核。
- Admin 部分结算。
- 商家退款申请。
- KOL 社媒账号被拒绝。
